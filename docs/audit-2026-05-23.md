## P1 — 보안 (defense-in-depth)

### A. ops-vm `api-server` 포트 0.0.0.0 바인드

`infra/ops-vm/docker-compose.yml` 의 `api-server.ports: "8080:8080"` → 호스트 0.0.0.0:8080. setup.md L20 ("ops-vm 의 Tailscale interface 에 bind") 의도와 다름. 현재 공개로 안 뚫린 유일한 이유 = ops-nsg 가 443/80/22 만 열어둠. NSG 만이 마지막 방어선.

**옵션**:
- `127.0.0.1:8080:8080` + worker-vm 접근 경로 별도 (현 방식 깨짐)
- `<ops-tailnet-ip>:8080:8080` (Tailscale 부팅 순서 의존)
- compose 의 `expose:` 만 쓰고 Caddy 로만 노출 + worker 는 다른 경로

선택 후 worker-vm `AIRFLOW__EDGE__API_URL` 도 일관성 검토.

### ~~B. lol-list PAT 평문 노출~~ — 해결 (2026-05-24)

ops·worker `lol-list` remote URL 에 PAT plaintext 임베디드 → SSH ed25519 deploy key 로 전환 완료. mac-server / ops-vm / worker-vm 셋 다 동일 패턴 (read-only deploy key per host). 잔여: 사용자 GitHub Settings → Personal access tokens 에서 노출됐던 PAT (`github_pat_11BK7JB3Y0JAOR...`) revoke.

### C. 공개 UI 의 SimpleAuthManager — rate limit / IP 화이트리스트 없음

`airflow.<your-domain>` 가 공개 HTTPS 로 노출, SimpleAuthManager 는 Apache 공식이 "dev/test only" 라 못박은 manager (`decisions.md` R3 에 인지됨). brute force 가능.

**옵션** (한 개만 골라도 충분):
- Caddy `@allowed { remote_ip <본인IP/32> }` — SSH 와 동일 정책, tailnet 은 항상 통과
- Caddy rate_limit module 로 `/login` 제한
- R3 트리거 — FabAuthManager 도입

minimal-disposable 철학에는 IP 화이트리스트가 자연스러움.

## P2 — 운영

### C. `airflow-logs` 볼륨 무한 증가

api-server·scheduler·dag-processor·edge-worker-ops 4개가 공유. 정리 정책 없음 → boot vol (125 GB) 시간 문제로 채워짐. docker log driver `max-size` / `max-file` 또는 Airflow 측 정책. Phase 8 모니터링 전이라도 필요.

### D. Caddy 보안 헤더 누락

HSTS, X-Frame-Options, X-Content-Type-Options 등 미설정. Caddyfile 한 블록 추가로 끝.
